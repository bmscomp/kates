# Jars in the Apache Kafka tarball that tester/Dockerfile swaps for patched
# releases from Maven Central. Kafka 4.3.1 ships these with known CVEs that
# the next 4.3 patch release already fixes upstream (the 4.3 branch moved
# Jetty, jline, lz4-java, Jackson and log4j after 4.3.1):
#
#   Jetty 12.0.34   CVE-2026-10050 (jetty-security, HIGH), CVE-2026-10051,
#                   CVE-2026-6790, CVE-2026-8384 -> 12.0.39
#   jline 3.30.4    CVE-2026-56740, CVE-2026-56741 (bundled jline-remote-telnet,
#                   HIGH), CVE-2026-77420/77421/77422 -> 3.30.17
#   lz4-java 1.10.2 CVE-2026-59949 (at.yawk.lz4 fork; no fixed 1.10.x) -> 1.11.3,
#                   the version kates/pom.xml pins
#   Jackson 2.21.2  CVE-2026-54512, CVE-2026-54513, GHSA-r7wm-3cxj-wff9 (HIGH)
#                   -> 2.21.7; jackson-annotations stays at 2.21
#   log4j 2.25.4    CVE-2026-49844 -> 2.25.5
#
# The list is written for ONE Kafka release, named on the `kafka` line. The
# build refuses any other KAFKA_VERSION, and refuses a line whose jar the
# tarball does not contain, so a Kafka bump cannot leave two versions of a
# library on the classpath: review every line against the new tarball, drop
# the ones it already fixes, and move the `kafka` line.
# scripts/check-versions.sh holds the `kafka` line to the Dockerfile's
# KAFKA_VERSION.
#
# Format: <jar in /opt/kafka/libs> <Maven Central path of the replacement> <sha256>
