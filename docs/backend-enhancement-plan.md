# Backend Enhancement Plan (kates/)

Audit date: 2026-07-21. Scope: the Quarkus backend under `kates/` — 181 main + 47 test Java files, Quarkus 3.15.7 LTS, Java 21. All file/line claims below verified against source.

The backend is in good architectural shape: clean resource → service → persistence layering, transactional outbox + idempotent event handling, Flyway-owned schema (V1–V15, `clean-disabled`), externalized fault-tolerance timeouts, persisted audit trail, custom readiness/liveness, structured JSON logs + OTel tracing, non-root multi-stage images with generational ZGC. The gaps cluster in four areas: **secrets/security posture, unbounded in-memory state, input validation, and test/CI depth**.

P3-4 (blocking/reactive consistency) also deferred as a signature-cascade refactor. Remaining LitmusChaosProvider internal poller still uses the common pool (low frequency; noted for follow-up).
> **Week 3 complete** — P2-1 ✓ (maven-failsafe + Testcontainers: `PersistenceIT` runs Flyway V1–V18 on real PostgreSQL and proves the `jsonb @>` query executes natively (no H2 LIKE fallback), webhook registration round-trip/upsert, and scheduler-lease claim/steal/expiry semantics; `KafkaAdminIT` exercises the shared AdminClient against a real KRaft broker. `IntegrationTestProfile` forces re-augmentation since db-kind is build-time) · P2-3 ✓ (ApiKeyAuthFilter finally tested — 401/403/200 + public paths over HTTP with security enabled; WebhookUrlValidator unit-tested across all policy branches with IP literals, no DNS).

## P0 — Security criticals (do first, ~2 days)

**P0-1. Kill the `changeme` API key.** `kates/k8s/configmap.yaml:22` ships `KATES_API_KEY: "changeme"` in a plaintext ConfigMap and `application.properties:92` defaults to it — with `security-enabled=true`, every mutating endpoint (topic create/delete, consumer-group delete, chaos injection, `/api/security/pentest` which runs *active attacks* against the live cluster) is guarded by a public string. Actions: move the key to a Secret + `secretKeyRef`; fail startup in prod when unset (`@ConfigMapping` + validation or a StartupEvent check); switch `ApiKeyAuthFilter.java:63` from `apiKey.equals(token)` to constant-time `MessageDigest.isEqual`; extend coverage to gRPC (currently unauthenticated, reflection enabled).

**P0-2. SSRF protection for webhooks.** `webhook/WebhookService.java:129` POSTs to arbitrary user-supplied URLs (`URI.create(reg.url())`) with no filtering. Enforce at registration and at send time: https-only scheme, deny loopback/link-local/RFC-1918/metadata (`169.254.169.254`) after DNS resolution, optional allowlist config key.

**P0-3. Externalize DB credentials.** `application.properties:165–166` hardcode `kates/kates` and the k8s Deployment doesn't override them. Inject via env from the existing `-db` Secret (the Helm chart already creates one — align raw `k8s/` manifests with it). Plan `SASL_PLAINTEXT` → `SASL_SSL` for Kafka auth (line 197–198) as a follow-up.

**P0-4. Harden `k8s/deployment.yaml`.** No `securityContext` at all (the Helm chart's deployment is exemplary — copy from it): `runAsNonRoot`, `readOnlyRootFilesystem`, `allowPrivilegeEscalation: false`, drop ALL caps, seccomp `RuntimeDefault`. Longer term: retire raw `k8s/` manifests in favor of the chart (drift source).

## P1 — Reliability & correctness (~3 days)

**P1-1. Fix memory leaks.** Confirmed: `engine/TestOrchestrator.java:54` `heatmapRows` is populated (l.341) and read (l.492) but never removed while `activeHandles`/`runStartNanos` are cleaned — grows per run forever. Add removal alongside the existing cleanup. Also bound: `report/ReportGenerator.reportCache` (manual evict only — add size cap/TTL, e.g. Caffeine), `service/SecurityService.scoreHistory` (never trimmed), `engine/DataIntegrityVerifier.consumedCounts` (one entry per record — aggregate instead).

**P1-2. Bean validation.** `hibernate-validator` is on the classpath with a working `ConstraintViolationExceptionMapper`, yet the codebase has exactly one `@Valid` and one `@NotNull`. Annotate `TestSpec` (num-records, batch/message sizes, producer counts, throughput, duration — these drive Kafka load generation), `CreateTestRequest`, webhook/baseline/schedule requests; add `@Valid` on request bodies. Stop leaking internals: `GlobalExceptionMapper.java:48` returns `root.getMessage()` on 500s.

**P1-3. Small latent bugs.** Delete the unused, never-shut-down `ScheduledExecutorService` field (`api/TestResource.java:52` — leaks a non-daemon thread); paginate the `findByStatus` branch (`TestResource.java:174–178` returns the full list while other branches page); resolve the CORS foot-gun (`quarkus.http.cors.origins=*` at properties:87 is dead config since `quarkus.http.cors=true` is never set — enable deliberately with a real origin list or delete).

**P1-4. Persist in-memory state that must survive restarts.** `WebhookService.registrations` is a `CopyOnWriteArrayList` (l.29) — registrations vanish on restart even though the DLQ is persisted; move to a table (entity + Flyway migration). Same for `SecurityService.savedBaseline`.

**P1-5. HA-safe scheduling (pre-req for replicas>1).** All 8 `@Scheduled` jobs (outbox drain 2s, DLQ, reapers, cleanup) fire on every replica. Add DB-level locking (e.g. `SELECT … FOR UPDATE SKIP LOCKED` on outbox rows — smallest fix) or leader election before ever scaling past `replicas: 1`.

## P2 — Test & CI depth (~1 week)

**P2-1. Real integration tests.** Tests run on H2 (`MODE=PostgreSQL`, `drop-and-create`, Flyway disabled — `src/test/resources/application.properties:74–79`), so Flyway V1–V15, the `jsonb @>` native query (`TestRunRepository.java:108`), GIN indexes, and real AdminClient paths are never exercised. Add Testcontainers (Postgres + Kafka/Redpanda) behind `maven-failsafe` + `@QuarkusIntegrationTest`; add Awaitility for async flows (outbox, webhooks, schedulers). Target the riskiest first: migration drift, jsonb queries, orchestrator lifecycle.

**P2-2. CI gates.** `mvnw verify` is the only backend gate. Add: jacoco (report + threshold), `spotless:check` (spotless is configured but **unbound** — no `<executions>` in pom, so formatting is unenforced), OWASP dependency-check or Trivy/Dependabot (the pom manually pins `kafka-clients` 3.9.0 and netty for named CVEs — tooling should drive when pins appear/drop), optionally SpotBugs.

**P2-3. Coverage debt.** 47 tests vs 181 main files; `disruption` (26 files) has 1 test, `security/ApiKeyAuthFilter` none, `grpc`/`config` none, `report` 1/9. Prioritize ApiKeyAuthFilter (fast, security-relevant) and disruption safety guards.

## P3 — Architecture & performance (~1 week, incremental)

**P3-1. Decompose god classes.** `service/SecurityService.java` (1548 lines, ~15 endpoint behaviors, all returning `Map<String,Object>`) → split into audit/pentest/TLS/CVE/ACL services with typed DTOs (also fixes weak OpenAPI schemas). `service/ClusterTopologyService.java` (1332) similarly. `engine/TestOrchestrator.java` (748) — extract heatmap/metrics bookkeeping.

**P3-2. Unify Kafka client usage.** `disruption/KafkaIntelligenceService` builds a fresh AdminClient per poll (l.71, 138, 251) while `KafkaAdminService` maintains a shared, circuit-broken client — route through it. Reuse producers in `KafkaClientService` hot paths.

**P3-3. Executor hygiene.** Chaos/resilience/CDC `CompletableFuture.supplyAsync` runs blocking Kafka/K8s I/O on the common ForkJoinPool — move to a managed executor (or virtual threads, already used in WebhookService — bound the fan-out). Replace the raw `new Thread` poller in `ShareGroupConsumerService:84`.

**P3-4. Blocking/reactive consistency.** `ClusterResource` is `@Blocking` yet consumes `Uni`-returning services (pipelines built then blocked). Pick one model per path; simplest is dropping the Uni wrapping where callers block anyway.

**P3-5. Quarkus LTS bump.** 3.15.7 → 3.20 LTS (then current). Do after P2-1 lands so integration tests catch regressions; revisit the CVE pins on each bump.

> **P4 (partial) complete 2026-07-21** — done: OTel `deployment.environment` no longer unconditionally "production" (env-overridable default + `%dev`/`%test` overrides so non-prod traces are tagged correctly); `Dockerfile.native` JNI extraction now fails the build loudly if any zstd/lz4/snappy native lib is missing instead of silently shipping a runtime-crashing image. ## Suggested sequence

Week 1: P0 (all) + P1-1 + P1-3. Week 2: P1-2, P1-4, P1-5 + P2-2. Weeks 3–4: P2-1, P2-3, then P3 incrementally. P4 opportunistic.

Acceptance: no default credentials anywhere in repo or manifests; webhook URLs filtered; zero unbounded caches touched per-run; every request body validated; CI enforces formatting, coverage, and dependency CVEs; integration suite runs Flyway + jsonb + Kafka against real containers; no scheduled-job duplication at replicas>1.
