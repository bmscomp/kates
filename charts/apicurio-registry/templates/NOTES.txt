Apicurio Registry {{ .Chart.AppVersion }} — release {{ .Release.Name }} in namespace {{ .Release.Namespace }}.

1. Reach the REST API / web console:
{{- if .Values.ingress.enabled }}
{{- range $host := .Values.ingress.hosts }}
  {{- range .paths }}
  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ $host.host }}{{ .path }}
  {{- end }}
{{- end }}
{{- else }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "apicurio-registry.fullname" . }} 8080:{{ .Values.service.port }}
  open http://localhost:8080
{{- end }}

2. Kafka backing (KafkaSQL storage — no bundled broker):
   bootstrap:  {{ include "apicurio-registry.kafkaBootstrapServers" . }}
   auth:       {{ .Values.global.kafka.securityProtocol }}/{{ .Values.global.kafka.saslMechanism }},
               JAAS config from Secret "{{ .Values.global.kafka.saslJaasConfigSecretName }}"
               (provisioned as a KafkaUser by the kafka-cluster chart)
{{- if .Values.kafkaTopics.create }}
   topics:     {{ .Values.kafkaTopics.journalName }} + {{ .Values.kafkaTopics.snapshotsName }}
               (KafkaTopic CRs in namespace "{{ .Values.kafkaTopics.namespace }}",
               cleanup.policy=delete, infinite retention)
{{- else }}
   topics:     NOT managed by this chart (kafkaTopics.create=false) — ensure
               kafkasql-journal/kafkasql-snapshots use cleanup.policy=delete
               with retention.ms=-1 and retention.bytes=-1, or the registry
               will refuse to start.
{{- end }}

3. Health + metrics are on the management port ({{ .Values.service.managementPort }}):
   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "apicurio-registry.fullname" . }} 9000:{{ .Values.service.managementPort }}
   curl http://localhost:9000/health/ready ; curl http://localhost:9000/metrics

4. Smoke test:
   helm test {{ .Release.Name }} -n {{ .Release.Namespace }}
